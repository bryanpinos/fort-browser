# Fort — project context for Claude Code

## What this is
**Fort, the Safe Home Browser** (renamed from Hearth on 2026-11-02). The theme
is a kids' blanket fort: their own space, built at home, with parents deciding
who gets in. Use "Fort" in UI and docs and `fort` in identifiers (bundle ID
`dev.pinos.fort`, repo `fort-browser`, relay header `x-fort-token`). Keep the
theme light and kid-friendly; never militaristic.

An open-source iOS/iPadOS browser for parents who run their own network. Think
"Island browser for parents": policy enforcement lives in the browser, and the
policy source is the parent's own infrastructure (Tailscale/WireGuard tunnel,
UniFi/pfSense gateway, NextDNS/Pi-hole), not a vendor cloud. No account, no
subscription, no telemetry to anyone but the parent.

Owner: Bryan (fortsafebrowser@gmail.com). MIT licensed. Paid Apple Developer account.
First deployment target: a family's iPads, locked down
with Screen Time (Safari hidden, app installs/deletes blocked), so Fort is the
only browser on the device.

## Hard constraints
- **WebKit only.** US App Store guideline 2.5.6 requires WebKit; alternative
  engines are EU-only. The app is a Swift/SwiftUI shell around `WKWebView`.
  Do not propose Chromium/Blink on iOS. A macOS Chromium sibling is a
  far-future idea, not in scope.
- **iOS 17+**, Swift 5.10, SwiftUI with `@Observable` (Observation framework),
  no Combine, no third-party dependencies unless clearly justified.
- **Fail closed.** Any error in the gate or proxy must mean "no browsing",
  never "fall back to direct".
- **Parent-owned data.** Nothing leaves the device except to endpoints the
  parent configured.
- Project file is generated by **XcodeGen** from `project.yml`. Never hand-edit
  or commit `Fort.xcodeproj`; edit `project.yml` and regenerate.

## Architecture (Sources/)
- `Config/GateConfig.swift` — the whole policy as one Codable struct. This is
  the public contract: JSON pasted in-app, fetched from a URL, or pushed via
  MDM AppConfig (`com.apple.configuration.managed` → `config` key, JSON string).
  Changing field names is a breaking change; add fields with defaults.
- `Config/ConfigStore.swift` — precedence: managed config > UserDefaults > defaults.
  SHA-256 parent PIN. Import from paste/URL, export via ShareLink.
- `Gate/NetworkGate.swift` — polls `probeURL`; only 2xx = connected. If
  `probeURL` is nil the gate is `.open` (plain filtered browser mode, also what
  an App Store reviewer would see).
- `Browser/TabsModel.swift` — Fort's tabs (max 8, restored on relaunch;
  `-fort.noTabRestore YES` in UI tests). Builds every tab's WKWebView with the
  same safety setup; sets the proxy on the shared default data store.
- `Browser/BrowserModel.swift` — one tab: chrome state + its WKWebView and
  `BrowserView.TabCoordinator` (the per-tab policy delegate).
- `Config/FavoritesStore.swift` + `UI/StartPageView.swift` — start-page tiles:
  parent favorites (`GateConfig.favorites`) plus each kid's (☆, per iPad).
- `Browser/BrowserView.swift` — container showing the selected tab's `WKWebView`.
  Proxy pin via `WKWebsiteDataStore.proxyConfigurations` (Apple relay, SOCKS5
  or HTTP CONNECT); `allowFailover = false` everywhere.
  Allow/deny enforced in `decidePolicyFor`; denylist also compiled into a
  `WKContentRuleList` so blocked hosts can't load as sub-resources. Only
  http/https/about schemes. Popups collapsed into the same view.
- `Browser/RelayForwarder.swift` — loopback CONNECT proxy used when the relay
  needs a client certificate: WKWebView can't present one on a relay hop
  (Apple FB25401454), Network framework can. Per-launch Basic credentials,
  80/443 only, 504 if the relay stalls (e.g. pending Local Network prompt).
  `forwarderTrace` prints `FORT-FWD` lines in DEBUG builds only.
- `Config/ClientIdentityStore.swift` — the relay client cert (.p12 + password)
  in the keychain, ThisDeviceOnly; imported in Parent settings, never part of
  `GateConfig`. iOS needs legacy-encrypted .p12 (`step ... p12 --legacy`).
- `Browser/SafeSearch.swift` — rewrites Google/Bing/DDG URLs to strict mode.
- `Browser/BrowserModel.swift` — observable chrome state; owns a weak WKWebView ref.
- `Logging/ActivityLogger.swift` — 500-entry local ring buffer plus batched
  JSON POST to `logEndpoint` every 30s (retries on failure).
- `UI/` — `ContentView` (address bar + blur/overlay gate), `GateOverlay`
  ("Open Tailscale" via `tailscale://` URL scheme + "Check again"),
  `PINPromptView`, `ParentSettingsView` (form that round-trips GateConfig),
  `ActivityLogView`.
- `App/FortApp.swift` — wires the three observables into the environment;
  gate starts/stops with scene phase; logs flush on background.

## Home side (server/)
`server/relay/` is the production path: Envoy relay (HTTP/2 CONNECT over
TLS, mutual TLS against a private "Pinos Fort Client CA" with a watched
device allowlist, token as second check) plus lego for its cert. Deployed on
the NAS as `fort-relay`; details in the homelab wiki (wiki.example.com).
The older `docker compose up` stack below gives: nginx probe (`/ok` → 200, also serves `fort.json`
for one-URL device setup), Squid HTTP CONNECT proxy restricted to
tailnet/LAN source ranges, and a tiny Python JSONL log collector. Bryan's
real deployment is on a UGREEN NAS reachable over Tailscale at a 100.x address;
page traffic exits his UniFi UCG-Fiber so its content filter applies.
